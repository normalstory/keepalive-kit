# ntfy — 알림 채널로 쓸 때

- **last-verified**: 2026-10-20 (취소 동작은 **5회 실측**)
- **출처**: https://docs.ntfy.sh/publish/
- 라이선스: Apache-2.0 / GPLv2 · 가입 없이 무료 · 셀프호스팅 가능

## ⚠ 공개 토픽은 읽기도 가능하다

토픽 이름은 사실상 비밀번호다. 흔히 "추측 불가능한 이름을 쓰라"고만 안내되는데,
**그 이유가 발행뿐 아니라 구독·조회까지 열려 있기 때문**이라는 점은 덜 알려져 있다.

```bash
curl "https://ntfy.sh/<topic>/json?poll=1&since=all"
# → 지난 메시지가 제목·본문·링크까지 전부 나온다
```

**함의**: 알림 본문에 제3자 개인정보를 실으면 안 된다. 이름·연락처·문의 내용은
로그인이 필요한 관리자 화면에서 보고, 알림은 "볼 것이 생겼다"는 신호까지만 담는다.

같은 이유로 **액션 버튼 헤더에 비밀을 싣지 않는다** — 토픽이 새면 비밀도 샌다.

## ⚠ 예약 메시지 취소는 **비결정적**이다 (5회 실측)

문서에는 예약 발송(`Delay` 헤더, 최대 3일)과 취소가 함께 설명돼 있다:

> *"DELETE `/<topic>/<sequence_id>`, 또는 GET `/<topic>/<sequence_id>/delete`"*

**실측 결과 — 될 때도 있고 안 될 때도 있다.**

| 시도 | DELETE 응답 | 예약 메시지 |
|------|-------------|-------------|
| 1 | 200 `message_delete` | **도착** (취소 실패) |
| 2 | 200 `message_delete` | **도착** (취소 실패) |
| 3 | 200 `message_delete` | 미도착 (취소 성공) |
| 4 | 200 `message_delete` | 미도착 (취소 성공) |
| 5 | 200 `message_delete` | **도착** (취소 실패) |

동일 조건(12초 예약 → 즉시 DELETE → 22초 대기 → 폴링)에서 **5회 중 3회 실패**했다.
응답은 매번 200이고 `event: "message_delete"` 로 같다. **응답만 보면 구분할 수 없다.**

`message_delete` 는 앱에게 "이 알림을 화면에서 지워라"라고 알리는 이벤트다. 서버의 예약
취소까지 함께 처리되는지는 타이밍/서버 상태에 따라 달라지는 것으로 보인다.

### 결론: dead man's switch 로 쓰지 말 것

"크론이 멈추면 경고" 를 ntfy 예약+취소로 만들면, 크론이 정상인데도 **절반 가까운 확률로
오탐 경고**가 울린다. 일관되게 깨진 것보다 **간헐적으로 되는 쪽이 더 나쁘다** —
예측 불가능한 오탐은 알림 자체에 대한 신뢰를 무너뜨리고, 결국 진짜 경고도 무시하게 만든다.

> 경로 주의: `DELETE` 는 `/<topic>/<id>`, `/delete` 접미사는 **GET 전용**이다.
> 둘을 섞으면 404가 난다. 단 올바른 경로로 고쳐도 위 결과는 같다.

## 액션 버튼 — 이건 잘 동작한다

| 타입 | 동작 |
|------|------|
| `view` | URL을 연다 (브라우저) |
| **`http`** | **폰이 직접 HTTP 요청을 보낸다 — 브라우저가 열리지 않는다** |
| `broadcast` / `copy` | Android 인텐트 / 클립보드 |

`http` 액션은 "알림 받고 탭 한 번으로 조치" 패턴에 적합하다. `clear: true` 를 주면
실행 후 알림이 사라진다.

## ⚠ 탭 지점이 둘이다

- 알림 **본문** 탭 → `click` URL
- **액션 버튼** 탭 → `http`/`view` 동작

서로 다른 목적지를 가질 수 있다. 사용자에게 설명할 때 구분하지 않으면 혼동한다
(실제로 "버튼이 아니라 본문을 탭하고 실패로 오해"한 사례가 있었다).

## 한글·이모지 — JSON 발행을 쓸 것

> *"ntfy supports UTF-8 in HTTP headers, but not every library or programming language
> does. If non-ASCII characters are causing issues in the title (`?` 로 보임)…"*

헤더 모드 대신 루트(`POST https://ntfy.sh/`)에 JSON 본문으로 발행하면 안전하다:

```json
{ "topic": "...", "title": "제목", "message": "본문", "click": "...",
  "tags": ["envelope"], "priority": 4,
  "actions": [{ "action": "http", "label": "실행", "url": "...", "method": "GET", "clear": true }] }
```

한글·이모지 왕복은 실측 확인했다.

## 검증 방법

`scripts/doctor.mjs --live` 가 (NTFY_TOPIC 필요):

1. 토픽 읽기 가능성 — 발행 후 `?poll=1` 로 읽히는지
2. **예약 취소의 비결정성** — 3회 반복해 도착 여부를 센다

2번은 "취소를 신뢰할 수 없다"를 단언한다. 3회 모두 취소에 성공하면 **검사가 실패하고**
"ntfy가 동작을 고쳤을 수 있으니 재검토하라"고 알려 준다. 한 번이라도 도착하면
비결정적이라는 뜻이므로 현재 결론이 유지된다.
